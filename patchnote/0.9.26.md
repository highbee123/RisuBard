# RisuBard v0.9.26

캐릭터·프롬프트·모듈의 파일 저장 안전성을 보강하고 목록 손상 시 복구를 개선했습니다. 로어북 전체 검색과 로어·페르소나 빌더의 긴 본문 편집도 편해졌습니다.

## [편의성] 로어북 검색과 빌더 편집

- **그리모어 검색 정확도:** 과거 상태창의 문구가 현재 입력의 검색 조건으로 섞이거나 `여행` 같은 낱말이 성별 조건으로 오인되는 문제를 수정했습니다. 현재 입력에서 직접 언급한 이름·키를 우선 선택하며, 일반 서술의 다른 타입·성별 표현 때문에 해당 인물이 탈락하지 않습니다. 명시적인 조건 검색과 토큰·항목 한도는 유지합니다.
- **그리모어 검색 범위·진단:** 최근 대화 범위가 0이어도 마지막 유효 사용자 입력을 검색하고, 이어쓰기에서도 같은 입력을 유지합니다. 댓글·비활성 메시지는 제외하며 로어 매칭 기록에서 실제 해석한 입력과 후보 제외 이유를 확인할 수 있습니다.
- **키워드 매칭 방식 선택:** 로어북 설정의 드롭다운을 눌렀을 때 도움말이 대신 열려 옵션을 선택하지 못하던 문제를 수정했습니다.
- **새 챗 페르소나 유지:** 같은 봇에서 새 챗을 만들면 이전 챗의 페르소나를 이어받고, 기존 챗이 없는 새 봇은 마지막으로 선택한 글로벌 페르소나로 시작합니다.
- **모듈 활성화 범위:** 채팅 안의 모듈 창에서 `전체`는 모든 캐릭터의 모든 챗에, `챗`은 현재 캐릭터의 기존 챗과 앞으로 만들 새 챗에 항상 적용되도록 바로잡았습니다.
- **모듈 창 밀도:** 모듈별 `전체`·`챗` 텍스트를 숨기고 활성화 아이콘과 버튼을 작게 다듬어 한 화면에서 더 많은 모듈을 확인할 수 있습니다.
- **프롬프트 V2 편집:** 연속 입력 중 반복되던 전체 프롬프트 갱신을 줄이고, 블록 검색 아래에서 선택한 블록 또는 모든 블록의 일치 문구를 한 번에 교체할 수 있게 했습니다. 사이드바 미리보기 간격과 조건 미리보기의 커서 위치도 바로잡았습니다.
- **로어북 전체 검색:** 검색 대상을 `전체`로 바꾸면 이름과 키뿐 아니라 각 항목의 본문까지 한 번에 찾을 수 있습니다.
- **빌더 편집 상태 유지:** 로어 빌더의 컨텍스트 선택과 창·입력칸·원본/수정본 분할 크기를 기억합니다. 로어·페르소나 빌더의 원본과 수정본에는 세로 리사이즈와 항상 보이는 스크롤 영역을 제공하고, 로어 수정본의 `적용` 버튼은 `이전 초안` 아이콘 옆으로 옮겼습니다.

## [개선] 이름별 폴더와 직접 편집 가능한 저장 데이터

- **바드쨩 (Bard-chan):** 설정에서 켜면 BardWiki 검색 후보의 점수가 비슷할 때 짧은 후보 카드만 한 번 재정렬합니다. 바드쨩에 사용할 메인·보조 모델을 별도로 선택할 수 있고, 기본값은 꺼짐과 보조 모델이며 호출에 실패하면 기존 검색 결과를 그대로 사용합니다.
- **챗별 BardWiki 설정:** 설정 창을 간결한 3열 행으로 정리하고 모든 옵션에 역할·현재 챗 길이·평균 메시지 길이에 맞춘 추천값 도움말을 추가했습니다. 창의 왼쪽·아래쪽 핸들을 드래그하는 동안에는 가벼운 섀도우 윤곽만 보여 주고, 놓는 순간 크기와 2열·1열 배치를 한 번만 갱신하며 확정한 크기도 기억합니다. 현재 챗 값을 전역 기본값으로 바로 적용할 수 있고, 바드쨩과 응답·분석 단계의 사용자 메시지 제외를 챗마다 각각 설정할 수 있습니다.
- **캐릭터 가져오기 진행 표시:** CHARX·JPEG·PNG 가져오기 문구를 한국어와 영어로 현지화하고, 파일 읽기·압축 항목 확인·압축 해제·에셋 준비·저장·메타데이터 적용 단계를 구분했습니다. 파일 용량과 에셋 개수도 작업 중 계속 표시합니다.
- **파일 드롭 가져오기:** 앱 창에 `.risum`, `.risup`, `.js` 파일을 놓으면 각각 모듈·프롬프트 프리셋·플러그인 목록으로 가져옵니다. 형식별 로딩 창과 파일명이 포함된 완료 알림을 표시하며 실패 시 원인을 함께 알립니다.
- 구형 저장소의 첫 실행에서 변경 내용·임시 공간 추정치·원본 백업 경로를 안내하고 동의를 받습니다. 거부하면 서버를 종료합니다. 임시 복사본의 변환·검증이 끝난 후 기존 저장소 전체를 인접 `backups/`에 보존하고 V2 저장소로 전환합니다. 백업은 자동 삭제하지 않습니다. 빈 저장소와 V2 저장소, 앱 안에서 외부 백업을 가져올 때는 이 사전 안내가 나타나지 않습니다.
- 캐릭터·대화·모듈·페르소나·프롬프트를 이름별 폴더로 정리합니다. 같은 이름은 번호로 구분하고 내부 ID와 연결 관계는 유지합니다.
- 설명과 프롬프트는 Markdown, 로어북은 JSON, 에셋은 소유 폴더의 실제 파일로 저장합니다. 이미지 파일을 같은 경로로 교체한 뒤 새로고침하면 반영됩니다. 같은 옛 이미지를 참조하던 캐릭터·모듈·페르소나도 소유자별로 분리해 한쪽의 수정이 다른 쪽에 전파되지 않게 합니다.
- 기존 저장과 다른 프로그램의 백업을 저장 레이아웃 V2로 변환하며, 이전 파일·초안·복구 기록을 보존합니다. 누락된 에셋이 있는 백업은 현재 세이브를 교체하지 않습니다.
- **이관 필요 공간 절감:** 새 저장 구조를 만들 때 기존 저장소 전체를 중복 복사하지 않고, 실제로 생성할 파일과 이미지 기준으로 필요한 공간을 안내합니다. 원본 전체 백업을 보존하면서 Termux 등 저장 공간이 적은 환경의 부담을 줄였습니다.
- **이관 전 선택 백업:** 첫 실행 안내에서 보관 폴더를 지정해 `로컬 백업 생성`을 선택할 수 있습니다. 원본 전체 복사·검증이 끝나면 완료 메시지와 정확한 백업·복구 안내 경로를 표시하며, 이후 이관 또는 종료를 직접 선택합니다.
- 에셋의 실제 이미지 형식을 확인해 디스크 확장자를 정합니다. 예전 참조 이름이 `.png`여도 실제 WebP 이미지는 `.webp`로 펼치며 연결은 유지합니다.
- 새 이미지 저장·복사·백업 가져오기에서 파일 정본과 KV에 같은 이미지 바이트를 중복 저장하지 않습니다. 업로드가 소유 폴더에 안전하게 저장되면 내용이 같은 미사용 임시 파일만 정리합니다. 구형 복구 오브젝트는 자동 삭제하지 않으며, 일반 DB·설정 KV 읽기는 전체 에셋 목록을 불필요하게 로드하지 않습니다.
- 일반 화면의 읽기·저장을 문서 단위로 전환합니다. 캐릭터·모듈 본문은 필요할 때 읽고, 저장할 때 전체 `database.bin`을 재조립하지 않고 변경된 파일만 기록합니다. 구형 백업·API와 동기식 플러그인의 전체 데이터 접근은 별도의 호환 경로로 유지합니다.
- 첫 썸네일 요청은 해당 이미지의 경로만 검증해 표시하며, 수만 개의 에셋 경로를 한꺼번에 검사해 앱 전체가 멈추지 않습니다. 전체 검증은 이관·가져오기·쓰기·삭제 시 계속 수행합니다.
- CHARX·CHARX/JPEG와 이미지 포함 모듈을 가져올 때 큰 압축 이미지를 제한 병렬로 해제하고, 에셋을 Base64로 부풀리지 않은 바이너리 묶음으로 저장합니다. 실제 이미지에는 중복 체크섬 보조 파일을 만들지 않으며, 대형 에셋 인덱스의 공통 경로를 한 번만 검사하고 연속 묶음에는 직전 검증 결과를 재사용해 대량 가져오기 시간을 줄였습니다.
- 데이터 이전 페이지를 없애고 전체 백업 다운로드·복원과 설정 백업을 **시스템 → 백업** 한곳에 정리했습니다. 기존 로컬 백업과 RisuAI 백업은 전체 백업 복원에서 계속 가져올 수 있습니다.
- 다른 RisuBard V2 세이브에서 캐릭터·모듈·페르소나·프롬프트·로어북을 골라 현재 세이브에 합치는 기능을 추가했습니다. 연결된 항목은 자동 포함하고, 중복 ID·이름·이미지 키는 안전하게 분리하며, 원본을 변경하지 않고 하나의 원자적 작업으로 반영합니다. 확인 이후 원본이 바뀌면 다시 확인하도록 중단하며, 디스크 반영 도중 실패해도 시작 전 상태로 롤백합니다.

## [안정성] 저장 데이터 보존과 목록 복구

- **전환 후 반복 저장 수정:** 저장 응답의 JSON 필드 순서가 달라졌다는 이유로 같은 내용을 계속 저장하던 문제를 수정했습니다. 읽기·저장 응답 반영은 실제 변경과 구분하고, 자동 저장은 변경된 문서만 처리합니다.
- **저장 충돌 재시도 제한:** 409 충돌 시 해당 문서를 다시 읽어 서로 다른 필드의 변경만 병합한 뒤 한 번 재시도합니다. 같은 필드·메시지 내역의 충돌은 로컬 편집을 보존하고 자동 재시도와 반복 알림을 멈추며, 다른 문서는 계속 저장할 수 있습니다.
- **지난 메시지 편집:** 연필 아이콘을 누르면 편집 입력란에 즉시 포커스하고 커서를 기존 메시지 끝에 배치해 바로 수정할 수 있습니다.
- **사이드바 하이파 표시:** `메뉴에서 하이파 모달 보이기`를 끄면 사이드바의 하이파메모리 스위치도 함께 숨깁니다.
- **로어북 폴더 열림 유지:** 로어북 데이터가 저장 과정에서 새 객체로 갱신돼도 열린 폴더가 즉시 닫히지 않습니다.
- **로딩 상태 표시:** 캐릭터를 누르면 즉시 `Loading…`을 표시하고, 준비가 끝나면 닫습니다. 임의의 퍼센트나 완료 메시지는 표시하지 않습니다. 우측 하단에서 문서·썸네일·RisuRealm 요청을 확인할 수 있으며 실패와 이미지 응답 시간 초과도 구분합니다.
- **세이브 불러오기 확인창:** 저장하지 않은 대화를 덮어쓸 때 확인창이 저장 창 뒤에 가려져 로딩만 계속 보이던 문제를 수정했습니다. 확인을 마친 뒤에만 실제 불러오기 상태를 표시합니다.
- **시작 로고 유지:** 앱 시작용 RisuBard 로고를 스타일시트보다 먼저 요청하고, 본 화면의 로고가 준비될 때까지 초기 로고를 유지해 빈 화면이 번쩍이지 않게 했습니다.
- **개발 서버 재시작 범위:** 프런트엔드 수정은 Vite의 즉시 갱신만 사용하고, Node 서버는 `server/node` 코드가 바뀔 때만 자동 재시작하도록 감시 범위를 제한했습니다. 전체 재시작은 실행 창에서 직접 요청할 때만 수행합니다.
- **백업 복원 진행률:** 대용량 로컬·서버 백업을 가져올 때 업로드뿐 아니라 V2 파일 생성·검증·최종 반영 단계를 구분하고, 오래 걸리는 파일 생성과 반영 작업은 0~100%를 1% 단위로 표시합니다.
- **저장 표시 정확도:** 변경 여부만 확인하거나 저장할 내용이 없는 동안에는 디스켓 아이콘을 표시하지 않습니다. 750ms 안에 끝나는 짧은 저장은 표시를 생략하고, 오래 걸리는 실제 파일 커밋만 작고 정적인 아이콘으로 알려 반복 저장처럼 보이던 점멸을 없앴습니다.
- **데이터 경로 확인:** 서버 시작 로그에 실제로 연결된 데이터 루트의 절대경로를 표시합니다.

- **불완전한 저장 차단:** 아직 불러오지 못한 대화나 누락된 컬렉션으로 기존 데이터를 덮어쓰지 않도록 검증을 강화했습니다. 저장 실패 후 캐시에만 일부 변경이 남는 문제도 수정했습니다.
- **문서별 충돌 보호:** 외부에서 수정한 문서를 오래된 화면 값으로 덮어쓰지 않으며, 저장 응답을 기다리는 동안 새로 입력한 내용도 유지합니다. 구형 저장 요청과 문서 저장이 섞여도 이미 승인한 변경을 버리지 않습니다.
- **초기 로딩·복제 보호:** 첫 실행의 중복 비밀번호 설정 요청을 막고, 캐릭터 복제 저장이 실패해도 원본 본문을 보존합니다. 비선택 캐릭터의 마지막 대화 삭제도 저장에 반영합니다.
- **동시 편집·삭제 보호:** 불러오는 동안 바꾼 값과 플러그인의 원래 편집 대상을 유지합니다. 다른 접속에서 삭제한 항목을 오래된 화면 요약으로 다시 생성하지 않습니다.
- **이름 변경 중 복구:** 폴더 이동 도중 외부에서 하위 파일을 수정하거나 서버가 중단되는 상황의 검증·복구를 보강하고, 캐릭터와 대화 이름을 함께 바꿀 때도 형제 폴더 이름 충돌을 피합니다.
- **목록 복구 개선:** 새로 저장한 데이터는 캐릭터·프롬프트·모듈 파일과 순서 기록을 이용해 손상되거나 사라진 목록을 복구합니다. 저장 중 중단으로 체크섬이 맞지 않아 불러오지 못하는 경우의 복구도 보강했습니다.
- **가져오기 안전성:** 기존 백업과 저장 폴더를 임시 공간에서 검증한 뒤 캐릭터·대화·모듈·프리셋별 파일로 바로 정리합니다. 원격·콜드 스토리지 내용이 없거나 손상된 백업을 일부만 불러와 성공 처리하지 않습니다. 교체 전 데이터와 에셋의 복구 기록도 보존합니다.
- **설정·참조 보존:** 빈 설정 객체가 사라지거나 파일 경로 변환 때문에 데이터 ID와 참조가 달라지는 문제를 수정했습니다. 원본에 쓰지 않는 이관 리허설 도구를 추가했습니다.
- **삭제 상태 보정:** 이관 리허설에서 사용자가 삭제했다고 확인한 모듈 ID만 명시적으로 제외하고 관련 참조와 감사 기록을 정리할 수 있습니다. 이미지가 없다는 이유로 자동 삭제하지 않습니다.
- **모듈 이미지 누락 차단:** `.risum`의 이미지 개수와 실제 내용이 다르거나 파일이 잘린 경우 가져오기를 거부합니다. 내보내기도 누락된 이미지를 빈 파일로 대신하지 않고 오류로 알립니다.
- **CHARX 제외 목록 호환:** 프리빌트 에셋 제외 목록에 이미 삭제된 이미지 경로가 남아 있어도 이를 필수 파일로 오인하지 않고 캐릭터를 정상적으로 가져옵니다. 제외 목록 값 자체는 그대로 보존합니다.
