# RisuBard v0.9.26

저장 구조 V2로 캐릭터·로어북·프롬프트·이미지를 **이름별 폴더와 직접 편집 가능한 파일**로 정리했습니다. 필요한 문서만 읽고 변경된 파일만 저장해 로딩·저장 부담을 줄이고, AI와 외부 편집기를 활용한 제작도 쉬워졌습니다.

## [시스템] 저장 구조 V2 — 디스크에서 바로 다루는 제작 자료

- **이름으로 찾는 폴더:** 캐릭터·대화·모듈·페르소나·프롬프트를 이름별로 모았습니다. 같은 이름은 번호로 구분하며, 앱에서 이름을 바꿔도 내부 ID와 연결 관계는 유지됩니다.
- **직접 편집하는 문서:** 설명·첫 메시지·프롬프트는 Markdown, 로어북은 JSON, 대화는 JSONL, 이미지·음성은 일반 파일로 저장합니다. 해당 내용을 앱에서 내보내거나 전용 형식을 해독하지 않고 열고 검색할 수 있습니다.
- **AI와 함께 제작:** 앱에서 캐릭터나 모듈을 만든 뒤, 파일에 접근할 수 있는 AI 도구에 설명과 로어북을 읽히고 수정을 맡길 수 있습니다. 외부 편집기의 일괄 교정이나 이미지 편집기를 통한 기존 이미지 교체도 쉬워집니다.
- **독립적인 이미지 수정:** 같은 옛 이미지를 참조하던 캐릭터·모듈·페르소나도 소유자별 파일과 참조로 분리합니다. 한쪽 수정이 다른 쪽에 전파되지 않으며, 실제 이미지 형식에 맞는 확장자로 정리합니다.
- **변경 비교와 도구 활용:** 텍스트 파일을 비교해 무엇이 바뀌었는지 확인하기 쉬워졌습니다. 필요한 제작 문서를 골라 일반 파일 검색·비교·버전 관리 도구로 다룰 수도 있습니다.

대표적인 구조는 아래와 같습니다. 실제로 존재하는 내용만 파일로 만들며, 내부 관리 파일 등은 생략한 예시입니다.

```text
데이터 폴더/
├─ characters/
│  └─ 캐릭터 이름/
│     ├─ character.json          # 기본 정보
│     ├─ description.md          # 캐릭터 설명
│     ├─ first_mes.md            # 첫 메시지
│     ├─ lorebook.json           # 캐릭터 로어북
│     ├─ assets/                 # 이미지·음성
│     └─ chats/
│        └─ 대화 이름/
│           ├─ metadata.json
│           └─ messages.jsonl    # 대화 내역
├─ modules/
│  └─ 모듈 이름/                # module.json, lorebook.json, assets/ 등
├─ personas/
│  └─ 페르소나 이름/            # persona.json, persona_prompt.md, assets/ 등
├─ prompts/
│  └─ 프롬프트 이름/            # settings.json, 프롬프트 본문 .md 등
├─ lorebooks/                    # 전역 로어북
└─ shared/assets/               # 전역 배경·아직 소유자가 없는 이미지 등
```

**비교: V2 이전의 파일 저장 구조**

이전에도 일부 데이터는 파일로 나뉘어 있었지만, 폴더와 파일 이름이 내부 ID·해시 중심이어서 탐색기만으로 어떤 캐릭터의 설명이나 이미지인지 찾기 어려웠습니다. 아래 ID와 해시는 설명을 위해 줄인 예시입니다.

```text
데이터 폴더/
├─ characters/
│  └─ 7c4e…/                    # 캐릭터 내부 ID
│     ├─ metadata.json          # 설명·첫 메시지·로어북 등이 한 JSON 안에
│     └─ chats/
│        └─ a912…/              # 대화 내부 ID
│           ├─ metadata.json
│           └─ messages.jsonl
├─ presets/
│  └─ b8d3….json                # 프리셋 내부 ID
├─ modules/
│  └─ f2a6….json                # 모듈 내부 ID
├─ personas/
│  └─ c5e1….json                # 페르소나 내부 ID
└─ kv/
   ├─ manifest.json            # 이미지 등의 키와 실제 파일을 연결
   └─ objects/
      ├─ 4f8a…                 # 해시 이름의 이미지·호환 데이터 등
      └─ 9bd2…                 # 이름·확장자만으로 내용을 알기 어려움
```

더 오래된 설치에서는 `risuai.db`에 데이터를 저장하거나, 저장 키를 16진수로 바꾼 파일을 사용하기도 했습니다. 위 구조와 모두 동시에 존재한다는 뜻은 아니며, 설치·이관 이력에 따라 다릅니다.

V2에서는 **내부 ID로 캐릭터를 찾고 이미지 연결 정보를 따라가던 작업을, `캐릭터 이름/description.md`와 그 안의 `assets/`를 여는 작업으로 바꿨습니다.** 기존 JSON 안에 묶여 있던 제작 본문도 개별 문서로 꺼내 AI와 외부 편집기가 다루기 쉽게 했습니다.

**외부 편집 방법:** 앱에서 해당 내용을 편집 중이지 않을 때 기존 Markdown·로어북 JSON·이미지 파일을 수정하고 브라우저를 새로고침하세요. 실시간 자동 반영은 아니며, 이미지 교체는 같은 경로·파일명을 유지하고 JSON은 기존 형식을 지켜야 합니다. 새 항목은 앱에서 먼저 만들고, 내부 ID·`manifest.json`·목록/이미지 연결 파일이나 폴더 위치는 임의로 바꾸지 마세요. 다른 세이브의 항목을 합칠 때는 `V2 항목 가져오기`를 사용하세요.

## [성능] 필요한 만큼 읽고, 바뀐 내용만 저장

- **문서 단위 로딩·저장:** 캐릭터·모듈 본문과 대화는 필요할 때 읽고, 일반 저장에서는 전체 `database.bin`을 다시 조립하지 않습니다. 변경된 문서 안에서도 내용이 같은 파일은 다시 쓰지 않아 불필요한 처리와 디스크 쓰기를 줄였습니다.
- **대형 이미지 목록 대응:** 첫 썸네일을 표시하기 위해 모든 이미지 경로를 검사하던 부담을 줄였습니다. CHARX·JPEG·이미지 포함 모듈 가져오기도 압축 해제와 이미지 전송·저장 방식을 개선했습니다.
- **이미지 이중 저장 감소:** 새 이미지를 일반 파일과 내부 저장소에 중복 기록하지 않도록 바꿨습니다. 안전하게 옮겨진 미사용 업로드만 정리하며 구형 복구 파일은 자동 삭제하지 않습니다.
- **반복 저장 방지:** 실제 내용이 같아도 저장 응답의 필드 순서 차이 때문에 저장을 반복하던 문제를 수정했습니다. 저장할 내용이 없거나 짧게 끝나는 동안에는 디스켓 아이콘이 계속 점멸하지 않습니다.

성능 향상 폭은 데이터 규모·기기·플러그인에 따라 달라집니다. 전체 백업과 일부 구형 플러그인은 여전히 전체 데이터 처리가 필요하며, 이미지 독립 복사와 원본 백업 때문에 총 디스크 사용량이 반드시 줄어드는 것은 아닙니다.

## [시스템] 첫 실행 이관과 백업

- **전환 전 안내:** 구형 저장소로 처음 실행하면 변경 내용·필요 공간 추정치·원본 보존 경로를 보여 줍니다. `이관 시작` 또는 `프로그램 종료`를 선택하며, 빈 저장소와 이미 V2인 저장소는 이 단계를 생략합니다.
- **선택 가능한 로컬 백업:** 이관 전에 보관 폴더를 지정해 `로컬 백업 생성`을 실행할 수 있습니다. 원본 전체 복사·검증이 끝나면 완료 메시지와 정확한 백업·복구 안내 경로를 보여 주고, 이후 이관 여부를 직접 선택합니다.
- **원본 보존과 공간 절감:** 새 V2 파일을 임시 폴더에서 생성·검증한 뒤 기존 저장소 전체를 인접 `backups/`에 보존합니다. 필요 공간은 원본 크기의 3배가 아닌 실제 생성 계획으로 추정하며, 선택 백업에는 별도 공간이 필요합니다.
- **백업 메뉴 통합:** 전체 백업 다운로드·복원과 설정 백업을 `시스템 → 백업`으로 모았습니다. 기존 로컬 백업과 RisuAI 백업도 계속 복원할 수 있으며, 업로드·V2 파일 생성·검증·최종 반영 진행 상황을 구분해 표시합니다.
- **V2 항목 가져오기:** 다른 V2 세이브에서 원하는 캐릭터·모듈·페르소나·프롬프트·로어북을 골라 합칠 수 있습니다. 필요한 연결 항목을 함께 가져오고 중복 ID·이름·이미지를 분리하며, 원본 변경이나 반영 실패 시 작업을 중단하거나 되돌립니다.
- **설정 백업의 제한:** 모듈 이미지를 제외한 설정 백업은 단독 복원이 거부됩니다. 복원할 설정 백업에는 모듈 이미지를 포함해야 하며, 일반 전체 백업과 기존 RisuAI 로컬 백업에는 해당하지 않습니다.

PC와 Termux 모두 같은 V2 구조를 사용합니다. Termux의 활성 데이터는 앱 내부 저장소에 두고, 공유 저장소에는 완성된 백업 파일을 복사하세요. 실제 데이터 폴더의 절대경로는 서버 시작 로그에서 확인할 수 있습니다.

## [기능] BardWiki와 그리모어 검색

- **바드쨩 (Bard-chan):** BardWiki 검색 후보 점수가 비슷할 때 AI가 짧은 후보 카드를 한 번 재정렬하는 선택 기능을 추가했습니다. 기본값은 꺼짐이며 메인·보조 모델을 선택할 수 있고, 호출에 실패하면 기존 검색 결과를 사용합니다.
- **챗별 설정과 도움말:** BardWiki 설정을 간결하게 정리하고 옵션별 역할과 현재 챗에 맞춘 추천값 도움말을 추가했습니다. 창 크기를 기억하고, 현재 값을 전역 기본값으로 적용하거나 바드쨩·응답/분석 단계의 사용자 메시지 제외를 챗별로 지정할 수 있습니다.
- **그리모어 검색 정확도:** 과거 상태창이나 일반 서술이 현재 검색 조건에 섞이던 문제를 수정했습니다. 직접 언급한 이름·키를 우선하고, 최근 대화 범위가 0이거나 이어쓰기 중이어도 마지막 유효 사용자 입력을 사용합니다.
- **검색과 진단 편의:** 로어북 검색 대상을 `전체`로 바꾸면 이름·키·본문을 함께 찾습니다. 검색 조건 선택을 방해하던 도움말 동작을 고쳤으며, 로어 매칭 기록에서 해석된 입력과 후보 제외 이유를 확인할 수 있습니다.

## [편의성] 제작과 대화 편집

- **빌더 작업 공간:** 로어 빌더의 컨텍스트 선택과 창·입력칸·분할 크기를 기억합니다. 로어·페르소나 빌더의 긴 원문과 수정본에 스크롤·세로 크기 조절을 제공하고, 로어 수정본의 `적용` 버튼을 `이전 초안` 옆으로 옮겼습니다.
- **프롬프트 V2 편집:** 연속 입력 중 반복 갱신을 줄여 타이핑 반응성을 개선하고, 선택한 블록 또는 모든 블록의 일치 문구를 교체할 수 있게 했습니다. 미리보기 간격과 조건 미리보기의 커서 위치도 바로잡았습니다.
- **파일 드롭 가져오기:** `.risum`·`.risup`·`.js` 파일을 앱 창에 놓아 모듈·프롬프트 프리셋·플러그인을 가져올 수 있습니다. 캐릭터 가져오기도 파일 읽기부터 이미지 저장까지 단계·용량·개수를 한국어와 영어로 안내합니다.
- **새 챗의 페르소나:** 같은 봇에서 새 챗을 만들면 이전 챗의 페르소나를 이어받습니다. 기존 챗이 없는 새 봇은 마지막으로 선택한 글로벌 페르소나로 시작합니다.
- **모듈 적용 범위:** 채팅 안 모듈 창의 `전체`는 모든 캐릭터의 모든 챗에, `챗`은 현재 캐릭터의 기존·새 챗에 적용되도록 바로잡았습니다. 활성화 버튼도 작게 정리했습니다.
- **편집과 화면 상태:** 지난 메시지의 연필 아이콘을 누르면 바로 본문 끝에서 편집할 수 있으며, 저장 후에도 열린 로어북 폴더를 유지합니다. 하이파 숨김 설정·세이브 확인창 가림·시작 로고 전환을 수정하고, 로딩·실패·이미지 시간 초과 표시를 보강했습니다.

## [안정성] 외부 편집과 저장 데이터 보호

- **문서별 충돌 보호:** 외부 파일 변경을 오래된 화면 값으로 덮어쓰지 않으며 저장 중 새로 입력한 내용도 보존합니다. 서로 다른 필드의 변경은 한 번 병합을 시도하고, 해결되지 않은 충돌은 로컬 편집을 유지한 채 반복 재시도를 멈춥니다.
- **불완전한 저장 차단:** 아직 읽지 않은 대화나 누락된 목록을 빈 데이터로 저장하지 않도록 보강했습니다. 캐릭터 복제 실패, 비선택 캐릭터의 대화 삭제, 다른 접속의 삭제와 플러그인 편집 대상 처리도 개선했습니다.
- **목록과 중단 작업 복구:** 목록이 손상되거나 사라지면 저장된 순서 기록과 데이터 파일에서 복구합니다. 이름 변경과 저장 도중 중단되거나 외부 수정이 겹치는 경우의 검증·복구도 보강했습니다.
- **가져오기 검증:** 손상된 백업·누락된 이미지·잘린 모듈을 일부만 가져와 성공 처리하지 않으며 교체 전 데이터와 복구 기록을 보존합니다. CHARX 제외 목록에 이미 삭제된 이미지가 남아 있는 경우의 호환성도 수정했습니다.
- **포터블 접속 주소:** Linux·macOS 실행 스크립트의 기본 접속 포트를 `7777`로 맞춰 시작 시 올바른 주소를 열도록 수정했습니다.

자세한 저장 형식과 이관·외부 편집 안내는 [파일 저장 구조 문서](../docs/ko/file-native-storage.md)에서 확인할 수 있습니다.
