# simplified-architecture 재시도: 데이터 보존 경계

2026-09-08 조사 및 구현 기록. 당시 실사용 실패의 로그나 원본 손상 데이터는 확인하지 않았으므로, 개별 사고 원인을 확정하는 문서가 아니다. 보존 브랜치의 구현과 현재 코드에서 확인한 데이터 유실 경로 및 회귀 테스트 결과를 기록한다.

## 보존된 구현

`refactor/simplified-architecture`의 끝점은 `96cf96d`다. 이 브랜치는 이미 현재 `main`의 조상이며 새로 병합해도 변경이 생기지 않는다. 파일 저장 전환은 `26e6ff8`에서 시작했다. 따라서 현재 공개판 체크아웃의 저장 경계를 보완하는 방식으로 재시도했다.

## 확인한 실패 경로

| 경계 | 기존 동작 | 재현 결과와 수정 |
| --- | --- | --- |
| 전체 객체 → 엔터티 파일 | 누락된 컬렉션을 빈 배열로 간주하고 `sync`에서 기존 항목을 휴지통으로 이동 | 기존 항목이 있는 컬렉션이 빠진 동기화는 쓰기 전에 거부한다. 기존의 명시적인 빈 배열 삭제와 구형 데이터의 선택 필드 부재를 구분한다. |
| 지연 로딩 → 메시지 파일 | 본문이 없는 chat/stub를 빈 JSONL로 저장 | 캐릭터 chats 배열, 채팅 message 배열과 hydration을 검증하고 불완전한 데이터는 거부한다. |
| 엔터티 ID → 파일 경로 | 동일 ID가 같은 파일에 여러 번 기록됨 | 컬렉션·캐릭터·캐릭터별 채팅의 중복 ID를 쓰기 전에 거부한다. Windows의 대소문자 충돌도 포함한다. |
| 파일 정본 → 호환 캐시 | 캐시와 메모리를 먼저 변경한 뒤 파일 저장 시도 | 실제 HTTP 테스트에서 저장 실패 응답 뒤에도 캐시에 모듈이 빠져 있음을 재현했다. 파일 정본 커밋 뒤 캐시, 수락 revision, 메모리를 게시한다. 캐시 실패 시 revision을 수락하지 않아 다시 읽을 때 정본에서 복구한다. |
| 목록 유실 → 부팅 | 파일이 있어도 목록이 없으면 빈 저장소로 인식 | 파일에서 목록을 재생성하며 새 저장부터는 `settings/entity-order.json`에 소속·순서를 함께 보존한다. 이 기록이 있으면 손상된 목록도 복구하고 프리셋·채팅의 배열 위치를 유지한다. |
| 메시지 유실 → 내보내기 | 파일이 없으면 빈 대화 반환 | 명시적으로 읽기 실패 처리해 원본 유실을 빈 대화로 확정하지 않는다. |
| journal 재생 → 체크섬 | 본문 rename 직후 중단되면 이미 게시된 본문을 건너뛰면서 옛 체크섬을 유지 | 준비된 journal에 기록된 본문 해시와 실제 파일이 일치하면 체크섬 sidecar도 복구한다. |

기존 테스트는 정상적인 전체 객체 가져오기, 정상 sidebar 조회, 본문과 체크섬 게시가 모두 끝난 지점의 중단을 주로 검사했다. 이번 실패 입력과 체크섬 게시 전의 중단 구간을 다루지 못했다. 폴더가 생기는 것과 저장·재시작 전체 경로의 안전성은 별도로 검증해야 한다.

설계 문서에 적힌 `commitUserMessage`, `saveAssistantDraft`, `loadSidebarIndex` 기반의 개별 데이터 흐름도 일반 서버 경로에 연결되지 않았다. 저장소 함수 단위의 테스트만으로 전체 앱이 그 설계대로 동작한다고 판단한 점이 검증의 공백이었다. 이번 작업에서는 정상 데이터뿐 아니라 불완전한 HTTP 입력과 서버 부팅까지 확인했다.

## 재시도 범위

초기 안전성 수정은 기존 ID별 파일 형식을 유지했다. 이후 사용자의 명시적인 요청에 따라 `characters/<이름>/`, `prompts/<이름>/`, `modules/<이름>/`, `personas/<이름>/`의 이름 기반 레이아웃 V2로 확장했다. 정본 데이터 루트, 앱 코드, 생성 캐시의 기존 경계는 유지한다.

서버가 전체 호환 객체를 다시 조립하는 기존 경로는 남아 있으므로, 모든 엔터티의 개별 저장 API와 완전한 지연 로딩으로의 재설계가 완료된 것은 아니다. 원래 ID는 데이터 안에 유지하고 순서 기록에서 실제 경로와 연결한다. 같은 이름은 번호로 구분하고 형제 폴더를 재번호하지 않는다. 본문·로어북·에셋을 일반 파일로 펼치며 외부 이미지 교체는 다음 읽기에 반영한다. 이 작업의 테스트는 격리 복사본에서만 수행한다.

## 후속: 가져오기 게시 경계

- `.bin`, hex 폴더 경로, hex ZIP은 공통 변환·게시 함수를 이용한다. 입력의 자체 원격·콜드 저장소만 참조하며, 이전 사용자의 에셋을 이용해 빠진 내용을 채우지 않는다.
- 격리 정본에 변환 후 설정·확장 필드·메시지를 포함한 전체 객체 왕복 동등성을 확인한다. 경로용 ID와 데이터의 원래 ID를 분리하고 빈 설정 객체를 보존한다.
- 정본 디렉터리 보관, 새 파일, 인레이, 이전 KV manifest, 새 KV manifest를 한 journal로 게시한다. 중단 후 재생 시 이미 보관된 디렉터리를 다시 옮기지 않는다. 게시 오류 후에는 접근을 막고 재시작 복구를 요구한다.
- `trash/import-*/kv-manifest.json`이 참조하는 기존 객체는 GC에서 제외한다. 기존 데이터가 복구 기록에 남는 것과 UI에서 교체가 취소되는 것은 구분한다.
- 원본에 쓰지 않는 `scripts/rehearse-save-migration.cjs`로 별도 복사본에서 변환과 해시 검증을 수행한다. 이것은 원본 저장 경로의 실제 전환이나 전체 UI 검증을 대신하지 않는다.

빈 배열은 정상적인 삭제 요청일 수도 있다. 구조적으로 완전한 빈 snapshot의 의도까지 이 검증이 판별하지는 않는다. 향후 개별 엔터티 API로 전환한다면 삭제를 별도 명령으로 분리하고 안정 ID와 기준 revision을 요구해야 한다. 손상된 정본 본문을 추측해서 복원하지 않으며, 이전 버전에서 순서 기록 없이 목록을 잃은 경우에는 원래 배열 순서를 보장할 수 없다.

## 검증 방법

모든 검증은 임시 저장소와 격리된 로컬 서버를 사용한다. 실제 사용자 데이터, 실행 중 서버, 비공개판은 변경하지 않는다.

```powershell
node node_modules/vitest/vitest.mjs run --config vitest.config.server.ts server/node/user-data-safety.test.ts server/node/user-data-repository.test.ts server/node/file-store.test.ts server/node/db-cache-recovery.test.ts server/node/canonical-projection-sync.test.ts
node node_modules/vitest/vitest.mjs run --config vitest.config.compat.ts
```

재현 테스트는 수정 전 실패를 확인한 뒤 수정 후 통과시켰다. 통합 검증은 실제 HTTP 저장 실패 후 디스크의 호환 캐시·정본·다시 읽은 목록을 대조하고, 목록과 캐시가 모두 없는 상태에서 서버를 새로 시작해 캐릭터·프롬프트·모듈을 확인한다. 기존 백업 왕복, 에셋 보존, 원격 블록과 콜드 스토리지 이관도 함께 검사한다.

2026-09-08 후속 검증: 영향받는 서버 테스트 67개와 전체 호환 테스트 72개가 통과했다. 외부 실물 fixture가 필요한 5개는 자료 부재로 제외했다. 별도 검토에서 발견한 `.bak` 누락과 과거 manifest가 참조하는 에셋의 재백업 누락을 수정하고, 새 설치 복원 후 GC까지 수행하는 회귀 테스트로 확인했다.

실제 데이터는 원본에 쓰지 않는 격리 복사본에서 검증했다. 89,016개 파일의 원본 해시 불변, 캐릭터 31개·대화 60개·메시지 852개·모듈 19개·프리셋 10개의 전체 객체 변환/재로딩 일치를 확인했다. 별도 초안·이전 수정본 등 추가 파일 160개도 보존하고 해시를 확인했다. 기존 정본과 호환 DB의 차이는 기존 저장 과정에서 빠졌던 빈 설정 객체뿐이었다. 실제 앱 UI 확인·원본 저장 경로 전환·배포는 수행하지 않았다.

## 이름 기반 V2 추가 검증과 남은 경계

위 실데이터 성공 기록은 초기 스키마 1 안전성 수정에 대한 결과이며, 이름 기반 V2의 실데이터 변환 성공을 뜻하지 않는다. V2 테스트는 이름 중복·Windows 경로 충돌·ID 유지·초안 이전·본문 분리·디스크 에셋 교체·공유 사본 충돌·재시작·누락 에셋 차단을 별도로 검증한다. 첫 레이아웃 전환 전의 KV manifest도 복구용으로 고정해 이후 에셋 변경과 GC로 옛 참조가 사라지지 않도록 한다.

2026-09-08 V2 격리 리허설에서 스크립트 정규식을 에셋 경로로 오인하는 오류를 수정했다. 재시도에서는 세 모듈의 명시적인 이미지 참조에 해당하는 파일이 스냅샷에 없음을 확인해 게시 전에 중단했다. 사용자가 해당 모듈들은 이미 삭제한 항목이라고 확인했다. 따라서 누락 파일을 복원하거나 빈 데이터로 대신하지 않고, 사용자가 확인한 정확한 ID만 `--exclude-module-id`로 새 변환 복사본에서 제외한다. 활성화·소속 참조를 정리하고 제외 목록을 보고서에 기록하며, 원본 파일은 스냅샷과 변환 휴지통에 보존한다. 이미지 누락 자체를 삭제의 근거로 삼지는 않는다. 앞서 중단된 `migration-test-20260908-v2/converted`와 `migration-test-20260908-v2-verified/converted`는 완료된 V2 데이터가 아니다.

공식 위키의 기존 ID 경로 계약을 V2로 변경하는 작업은 자동 검토에서 사람의 승인 필요로 차단되어 미반영 상태다. 본 구현 문서와 사용자 문서는 변경 내용을 기록하지만 공식 계약 변경 승인을 대신하지 않는다.

V2 최종 자동 검증은 영향받는 서버 테스트 115개와 HTTP·백업 호환 테스트 80개가 통과했다. 실물 fixture가 필요한 5개는 제외했다. 준비된 journal이 남으면 후속 트랜잭션·HTTP 요청·지연 저장을 차단하고 재시작 복구를 요구한다. 일반 저장도 누락된 명시적 에셋 참조가 있으면 전환을 게시하지 않는다. 테스트 통과는 누락 에셋이 있는 실제 스냅샷의 전환 완료를 의미하지 않는다.

삭제 확인 후의 마무리 검증에서는 영향받는 서버 14개 파일의 106개 테스트, 전체 HTTP·백업 호환 80개 테스트, 모듈 처리 11개 테스트가 통과했다. 실물 fixture 5개는 계속 제외한다. `.risum`은 본문 잘림·선언한 이미지 개수 불일치를 이미지 저장 전에 거부하며, 내보내기도 누락 이미지를 빈 파일로 대체하지 않는다. 디스크 에셋 확장자는 실제 이미지 시그니처를 우선한다. 화면 빌드는 성공했고, 별도 범위 제한 코드 검토에서 중요·치명 결함은 발견되지 않았다. 이는 전체 UI 수동 검증이나 릴리즈 승인을 의미하지 않는다.

최종 실제 데이터 리허설은 `<workspace>\migration-test-20260908-v2-final\converted`에서 성공했다. `report.json`에서 원본 스냅샷 89,016개 파일의 해시 불변, 명시적으로 제외한 세 모듈과 관련 참조 외 전체 객체 왕복 동등성, 저장소 재개방 일치를 확인했다. 캐릭터 31·대화 60·메시지 852·모듈 16·페르소나 26·프롬프트 10이며 실제 에셋 파일은 78,115개다. 새 활성 파일 경로는 최대 168자였다. 포트 17777의 격리 서버를 두 번 기동해 HTTP 데이터 읽기, 삭제 모듈 부재, 모듈 이미지 응답의 디스크 바이트 일치, 정본 불변을 확인하고 종료했다(`server-verification.json`). 실제 원본 세이브 경로는 전환하지 않았다.
