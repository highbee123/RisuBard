# 소유자별 에셋 단일 저장 구현 계획

**Goal:** 소유자별로 독립 편집 가능한 일반 이미지 파일을 유지하면서 활성 KV에 같은 이미지 바이트를 중복 저장하지 않는다.

**Architecture:** 이름 기반 V2에서 이미지 읽기·쓰기·복사·가져오기는 파일 정본을 사용한다. KV에는 DB·캐시 등 비에셋 호환 데이터만 유지한다. 예전 파일과 복구 manifest는 자동 삭제하지 않는다. 여러 소유자가 같은 논리 키를 쓰는 경우는 소유자별 참조를 안전하게 분리하며, 단순히 이미지 내용이 같다는 이유로 합치지 않는다.

**Tech Stack:** 기존 Node.js 파일 저장소·journal·Vitest. 현재 공개판 브랜치에서 작업하며 원본 데이터·비공개판·공식 위키 계약·릴리즈는 변경하지 않는다.

- [x] `server/node/owned-asset-kv.test.ts`: 단일·일괄·비동기 쓰기와 복사에서 새 이미지 KV 오브젝트가 생성되지 않고 재시작·삭제·일반 KV 키가 정상 동작하는 실패 테스트를 작성한다.
- [x] `server/node/file-kv.cjs`: 소유 파일과 asset index, KV manifest 변경을 같은 journal로 게시한다. 아직 소유자가 정해지지 않은 업로드도 일반 파일로 저장하고, 기존 복구 객체는 유지한다.
- [x] `server/node/server.cjs`, `test/compat/file-native-safety.test.ts`: 가져온 이미지의 정본 게시가 보장된 항목만 KV 저장에서 제외하고, 백업 왕복 및 불완전 입력 거부를 검증한다.
- [x] 소유자 독립성 조사 결과에 따라 참조 분리를 구현하고, 캐릭터·모듈·페르소나 각각의 디스크 수정이 다른 항목으로 전파되지 않음을 검증한다.
- [x] 복구 기록을 지우지 않는 KV 중복 참조 정리와 안전한 검사 경로를 제공한다. 실제 세이브 정리는 별도의 검증된 절차로만 실행한다.
- [x] 영향받는 서버·호환 테스트와 코드 검토를 수행하고 사용자 문서·최신 패치노트를 갱신한다. 실제 여유 공간이 늘었다고 측정 없이 주장하지 않는다.

## 검증 및 한계

- 저장 관련 16개 파일 153개 테스트 통과 후, 업로드 정리의 반복 탐색을 선형화하고 관련 42개 테스트를 추가 재검증했다.
- 전체 호환 테스트 84개 통과, 5개 생략. 클라이언트·모듈 테스트 14개 통과. 프로덕션 빌드 성공(CSS·번들 크기 등 경고는 남음).
- 코드 검토에서 확인한 페르소나 선택 참조와 업로드 임시 파일 중복 문제를 수정하고 독립 재검토했다. 이미지 참조 재작성 PATCH는 대화 본문까지 포함해 검사한다.
- 모듈 에셋을 의도적으로 제외한 설정 백업의 엄격한 가져오기 거부는 별도 릴리즈 전 해결 과제로 문서화했다. 누락 검증을 완화하지 않았다.
- 기존 KV 오브젝트·복구 manifest의 삭제 및 전체 DB 지연 로딩 재설계는 이번 작업에 포함하지 않는다.

## 격리 데이터 적용

- `<workspace>\migration-test-20260908-v2-final\converted`만 오프라인 갱신했다. 원본 사용자 세이브는 작업 대상으로 열지 않았다.
- 이미지 78,126개의 바이트 보존, 단일 경로와 하드링크 부재를 확인했다. 캐릭터 31개·모듈 16개·대화 60개·메시지 852개와 전체 DB 의미 왕복 일치를 확인했다.
- 활성 KV 이미지 참조 77,877개(6,535,280,281바이트)를 해제했다. 활성 이미지 KV 항목은 0개이며, 삭제한 KV 오브젝트는 0개다. 이전 manifest와 오브젝트는 복구용으로 보존했다.
- 변환 전 메타데이터 백업과 `independent-assets-report.json`은 해당 격리 테스트 디렉터리에만 보관한다.
- 격리 서버를 두 번 시작해 HTTP DB 읽기·삭제 확인 모듈 부재·모듈 이미지 바이트 일치·정본 불변을 검증했고 테스트 서버를 종료했다.
